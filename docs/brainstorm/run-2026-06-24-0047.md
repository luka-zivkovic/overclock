## test-actually-fails — STRONG
- **Moat axis:** artifact-to-action with a concrete DETERMINISTIC oracle (the test runner going red
  after a real code mutation). Stateless discipline gate; not memory, not right-sizing. Merges the
  KILLed test-oracle-justifier framing into a mutate-and-rerun mechanism that dodges the self-oracle trap.
- **Baseline-gap finding:** useful-and-distinct. Mutation CLIs (Stryker incl. --incremental, mutmut,
  cosmic-ray, PITest) own the slow, configured, suite-wide CI campaign nobody runs in the inner loop;
  the targeted "did THIS just-written test actually constrain THIS function" single-mutation rerun at
  write-time is unowned. The oracle is REAL (a test-runner exit code after a genuine mutation), not the
  self-audit that killed test-red-triage / claim-evidence-audit / error-to-min-repro — same property
  that flipped repro-first and characterization-tests to STRONG. Distinct from those STRONG siblings by
  TRIGGER (a freshly-green NEW test) and MECHANISM (mutate-prod → rerun → restore). Honest caveats:
  (a) PACKAGING — the repo would now hold FOUR stateless test/edit discipline gates; (b) prong-1
  in-repo demand likely ~zero; (c) needs a hard restore-always safety contract + right-sizing.
- **Simulations (avgDelta 7.5):**
  - *Agent writes a Jest test for `calculateDiscount` whose expected value is computed by calling the
    function under test again (tautological assertion); suite goes green* — **delta 8.** Skill mutates
    the body (flips `*` to `+`), reruns only that test, sees it STILL pass = ground-truth the test
    constrains nothing; restores, rewrites the assertion against an independent literal, re-mutates to
    confirm red. Baseline ships the self-referential green and moves on; nothing in the inner loop
    exposes the tautology.
  - *Integration test mocks the email transport and asserts `toHaveBeenCalled()`, but `send()`
    early-returns behind a default-off flag, so the asserted call never happens yet the test passes* —
    **delta 7.** Skill comments out the `transport.send(...)` line, reruns, still-green proves the
    assertion isn't reaching dispatch (mock-and-assert-the-mock trap); restores, fixes the setup or
    finds the early-return bug. Baseline trusts a green that verifies nothing; Stryker would catch the
    class but nobody installs+configures+runs it on one just-written test mid-task.
- **Skeptic votes:** 3/3 worth building. All three: REAL deterministic oracle (mutate → rerun →
  demand red → restore), high daily frequency on a well-documented failure (agents reliably ship
  passes-by-construction tests), non-redundant vs mutation CLIs (which own the slow CI campaign),
  distinct from repro-first/characterization-tests by trigger + mechanism, and NOT the test-red-triage
  overlap case. Weakest link (unanimous): PACKAGING sprawl — four stateless test/edit discipline gates
  with overlapping should-NOT-trigger surfaces likely want ONE multi-mode test-discipline skill, and
  prong-1 in-repo demand is ~zero.
- **Decisive reason:** Useful and distinct under the corrected bar; the deterministic mutate-and-rerun
  oracle is genuinely new mechanism the existing siblings lack. The open question is WHEN/HOW to
  package it (a mode of a consolidated test-discipline family vs a fourth standalone trigger) and
  gathering real incidents — that gates build order, not the verdict.

  deletion the skill exists to prevent (the dep-advisory-triage kill reason). (4) Trigger collides with
  STRONG git-archaeologist (the recover-WHY-before-deleting gate).

## Run takeaways

- **review-comment-resolver (STRONG, contingent)** wins by being the CONSUME-side mirror of the

  thin-wrapper KILLs. But its load-bearing triage/draft legs are native-LLM, so it must earn its keep

The four KILLs reconfirmed the dominant failure modes:
- **native-LLM-collapse + self-referential audit** — scope-fence's semantic per-hunk verdict and
  pr-context-pack's reviewer brief are both one-shot reasoning over content already in context, already
  KILLed as tracker-sync / ticket-to-contract; the editor grading its own edits adds zero information.

  git-archaeologist on every leg, and its claimed unique edge (grep dynamic refs) produces FALSE
  NEGATIVES that green-light destructive deletes (dep-advisory-triage reason).
- **relabeled-lens / strictly-worse subset** — concurrency-hazard-scan is /code-review --high with a
  renamed prompt and no deterministic oracle; the lens is free via a one-line review request.

Headline recommendation: do NOT add either STRONG to the build queue yet. Resolve the
test-discipline-family packaging decision (now a four-gate cluster) and gather prong-1 demand for
