# External skill evaluation — 2026-06-22

These are **EXISTING, PUBLISHED third-party skills** evaluated for adoption into Overclock —
**not** internally generated candidates. Each already ships publicly and is freely installable
as-is. The question is not "is this a good idea" but: **should Overclock build, adopt, lift from,
or pass** given (a) what Overclock already ships and (b) that the skill exists as-is?

Verdicts: **ADOPT-AS-IS** (install the published skill, no Overclock rebuild) /
**BUILD-IN-OVERCLOCK** (real memory/right-sizing gap the published version misses) /
**INSPIRE** (lift one mechanism into an existing Overclock skill) / **PASS** (below the bar /
duplicative of Overclock's surface).

Baselines weighed: built-in `/simplify` + code-simplifier agent, `/code-review`,
`/security-review`, feature-dev (clarify-after-recon), plan mode, `/verify` + `/run`,
session-memory (lessons-learned / session-handoff), commit-push-pr, and CLAUDE.md as the
always-loaded behavioral-guideline home.

## ponytail — INSPIRE

- **Source:** https://github.com/DietrichGebert/ponytail
- **Verdict:** INSPIRE (votes: INSPIRE 3)
- **Pitch:** Persistent "lazy senior dev" persona forcing the simplest solution that works
  (YAGNI, stdlib-first, no unrequested abstractions); active every response with lite/full/ultra modes.

**Baseline-gap finding.** Stateless always-on simplicity persona — pure prompt-shaping. Touches
neither Overclock moat axis: no memory (nothing persists to `.ai/memory/`), and lite/full/ultra
is a manual intensity dial set by the user, not an automatic triage/altitude gate keyed to task
size or blast radius. The on-demand simplification job is already owned by the installed
`/simplify` command (which *applies* fixes) plus the code-simplifier agent and `/code-review`.
By firing every response it is exactly the persistent-persona-on-trivial-tasks bloat strategy.md
rule 3 warns against, in the saturated persona/prompt-shaping zone rule 2 says to judge hard.
The buildable kernel collapses to one CLAUDE.md altitude line — the same collapse that KILLed
repro-first and codemod-from-exemplar.

**Benchmark check.** The shipped agentic benchmark is genuine and unusually rigorous: headless
Claude Code editing tiangolo/full-stack-fastapi-template, 12 tickets, n=4, Haiku 4.5 →
−54% LOC / −22% tokens / −20% cost / −27% time, 100% safety retained. BUT it does not measure
what the pitch implies. An independent reproduction (Scott Logic, 2026-06-16) showed a 3-word
"Follow YAGNI principles" prompt roughly matched ponytail and a 7-word variant BEAT it on LOC
(6.9 vs 8.25 vs 10.4 baseline), and the benchmark's baseline was weak (prompted to offer
multiple options, inflating the delta). So the LOC/token/cost wins attribute to the YAGNI idea,
not the 100-line persona. The **only** reproducible persona-load-bearing differentiator: the
never-simplify-away-trust-boundary-validation rule preserved a path-traversal check the naive
yagni-oneliner arm dropped (went unsafe 1/4).

**Decisive reason.** Not ADOPT (persona adds near-zero standing value over one sentence and its
always-on firing is bloat Overclock avoids); not BUILD (no memory/right-sizing axis to improve).
The single verified survivor is the **safety floor** — *never simplify away trust-boundary
validation / security / data-loss / accessibility* — an INSPIRE sliver to fold into `/simplify`
or a CLAUDE.md altitude line.

## ponytail-review-and-audit — PASS

- **Source:** https://github.com/DietrichGebert/ponytail
- **Verdict:** PASS (votes: PASS 3)
- **Pitch:** One-shot over-engineering review of a diff (review) or whole repo (audit): ranked
  findings tagged delete/stdlib/native/yagni/shrink, ends with "net: -N lines possible".

**Baseline-gap finding.** Near-exact overlap with two installed built-ins. `/simplify` covers
its exact scope (complexity/over-engineering only; correctness/security/perf out of scope) and
goes further — it *applies* fixes, whereas ponytail-review lists only. `/code-review` covers the
report-only mode plus severity/effort tiers (low/medium/high/max/ultra) and `--fix`/`--comment`.
So both halves (list + apply) already exist in Overclock's surface. Fully stateless ("no
persistence across sessions") — no memory axis; lite/full/ultra is a manual flag, not blast-radius
right-sizing — does not even occupy the right-sizing axis. The delete/stdlib/native/yagni/shrink
tag taxonomy and "net: -N lines" footer are cosmetic output formatting, not a capability gap.
This is the saturated simplification-review zone (cf. review-router KILL: "stateless ceremony on
the most saturated axis").

**Benchmark check.** The cited benchmark is methodologically solid (n=4, fresh repo+context per
cell, real FastAPI codebase, adversarial safety execution) but **measures the wrong feature**: the
−54% LOC / −22% tokens headline comes from the always-on generative ruleset shrinking newly-written
feature code, not from the review/audit commands surfacing findings on an existing diff/repo. No
evidence the review/audit step finds more or more-actionable over-engineering than `/simplify` or
`/code-review`.

**Decisive reason.** Both halves of its value already ship in Overclock; no moat-axis gap; the
distinguishing element is cosmetic output format. Anyone who prefers the tag format can install
the published skill freely. No build or adopt-and-rebuild angle.

## ponytail-debt — PASS

- **Source:** https://github.com/DietrichGebert/ponytail
- **Verdict:** PASS (votes: PASS 3)
- **Pitch:** Harvest every `ponytail:` shortcut comment in the repo into one debt ledger
  (ceiling + upgrade trigger per row), flagging no-trigger rows as silent-rot risk.

**Baseline-gap finding.** Structurally coupled to one vendor's `ponytail:` marker, which only
exists if you adopted the parent Ponytail ruleset — so it is a satellite reporter for its own
convention, not a general tech-debt tool. The harvest is native Grep + LLM tabulation (the
native-LLM-collapse pattern the SHORTLIST has KILLed repeatedly). The optional persisted
PONYTAIL-DEBT.md is a flatter, weaker version of session-memory's `.ai/memory/` ledgers + inline
TODOs + issue trackers (the re-homes-memory-others-own KILL shape). The "no-trigger = silent-rot"
flag is a single boolean LLM judgment over a parsed comment — no defensible mechanism. Touches
neither moat axis: no cross-session memory, no right-sizing/triage gate. General debt-marker
harvesting is owned deterministically by todo-tree/leasot/ripgrep/IDE TODO panels and gh issues.

**Benchmark check.** The cited adoption (48.9k stars, 2.4k forks) and the −54% LOC / −22% token
n=4 benchmark all belong to the **parent** Ponytail generative ruleset, not this harvester. The
`/ponytail-debt` sub-command has zero independent usage counts or benchmark — prong-1 demand for
the debt-ledger specifically is effectively nil. Adoption is real but mis-attributed; discounted.

**Decisive reason.** No general baseline gap (vendor-convention-locked), neither moat axis,
mechanism is native Grep+tabulate, and durable state is owned better by session-memory + trackers.
Rebuilding would be a strictly worse vendor-locked duplicate. PASS.

## ponytail-gain — PASS

- **Source:** https://github.com/DietrichGebert/ponytail
- **Verdict:** PASS (votes: PASS 3)
- **Pitch:** Display ponytail's published benchmark medians as ASCII bars; explicitly refuses to
  invent per-repo savings numbers.

**Baseline-gap finding.** A single static print of another repo's benchmark medians — a "README
badge in the terminal." Touches neither moat axis: nothing to persist (the numbers are fixed
constants identical on every invocation in every repo) and nothing to right-size (no triage,
altitude gate, anti-triggers, or per-task variation — by design it refuses to compute anything
repo-specific). It is the structural inverse of an Overclock skill: deliberately stateless and
non-adaptive. Inseparable from its parent — installed alone in Overclock it would just render a
third party's marketing numbers, which is off-brand for a repo whose pitch is its own
independently-graded benchmarks. Prong-1 in-repo demand (re-rendering fixed constants) is zero.

**Simulated scenarios (avgDelta 1 — negligible).**
- "How much does ponytail save?" → prints a tidy ASCII scoreboard of static medians but still
  can't answer the dev's real "what will *I* save?" question. Baseline: the model answers from the
  same public benchmark in prose, adds the honest per-repo caveat (the same refusal the skill
  hard-codes, but reasoned), and handles follow-ups. **delta 1.**
- "Show ponytail's numbers for my README/comparison." → emits a fixed ASCII chart of a third
  party's numbers, no comparison. Baseline: model builds an actual side-by-side table against the
  dev's own tool in any format requested. **delta 1.**

**Benchmark check.** The parent ponytail benchmark is real and honest (n=4, Haiku 4.5, medians,
self-de-rates older single-shot 80–94% figures as inflated). But ponytail-gain does not RUN it —
it only DISPLAYS already-computed medians, so the benchmark substantiates the parent
decision-ladder skill, not this renderer.

**Decisive reason.** No moat-axis contact, zero recurring demand, meaningless standalone, and its
one virtue (refusing to fabricate numbers) is already a hard rule in session-memory and the
README's benchmarking discipline. Not even INSPIRE. PASS.

## karpathy-guidelines — PASS

- **Source:** https://github.com/multica-ai/andrej-karpathy-skills
- **Verdict:** PASS (votes: PASS 3)
- **Pitch:** Behavioral guidelines to reduce LLM coding mistakes: think-before-coding,
  simplicity-first, surgical changes, goal-driven execution (verifiable success criteria, loop
  until verified).

**Baseline-gap finding.** A stateless behavioral persona squarely in the saturated zone (rules
2-3), scoring zero on both moat axes. Memory: persists nothing across sessions — the inverse of
the moat; lessons-learned already *earns* such lines from observed corrections (evidence-counted,
deduped by meaning, promoted to CLAUDE.md only with consent), strictly stronger than a static
disclaimer. Right-sizing: one prose sentence about trivial tasks, not a triage/altitude gate with
anti-triggers; no rigor scaling — so it fires on every task (rule-3 bloat). Each of its four
behaviors is already owned by an installed *active* mechanism, not just a prompt:
think-before-coding → feature-dev clarify phase + plan mode; simplicity-first / surgical →
`/simplify` + code-simplifier + `/code-review`; goal-driven verify-loop → `/verify` + `/run`; and
CLAUDE.md is the always-loaded home for static behavioral guidance.

**Benchmark check.** The 41%→11% error-reduction claim fails verification: no methodology, sample
size, task set, error definition, or independent run — marketing copy on a viral template repo,
not attributable to Karpathy. Discounted. The ~100k+ GitHub stars measure template popularity, not
effectiveness, and only prove the skill is freely installable as-is — not that Overclock should
rebuild it.

**Decisive reason.** All three creation-bar prongs fail (zero logged in-repo incidents, no
baseline gap, no should-NOT-trigger eval since there is no triage gate). Every discipline it
preaches is already covered by CLAUDE.md + lessons-learned + `/simplify` + `/verify` + feature-dev.
A free version is installable; rebuilding adds nothing on either axis. PASS.

## what-did-i-get-done — PASS

- **Source:** https://github.com/cursor/plugins/blob/3347cbab/cursor-team-kit/skills/what-did-i-get-done/SKILL.md
- **Verdict:** PASS (votes: PASS 3)
- **Pitch:** Generate a concise work summary from git commits in a time range, filtered to the
  current user excluding merges, with the resolved date range and optional 2-5 bullets.

**Baseline-gap finding.** Collapses to one deterministic command
(`git log --author=<me> --no-merges --since/--until`) plus native LLM summarization — base-model
behavior the agent already performs on request, no scaffolding needed. Notably, session-memory's
docs **explicitly exclude** "human-facing summaries like PR descriptions or status reports" as a
non-trigger — Overclock deliberately treats status-report generation as NOT memory work. So this
neither duplicates an Overclock skill's core nor fills a hole; it occupies a space Overclock
intentionally carved out. Neither moat axis touched: output is ephemeral status prose (nothing
persists to `.ai/memory/`), and "be concise, omit cosmetic changes" is output-style filtering, not
rigor-scaling. The native-LLM-collapse-over-a-single-deterministic-command KILL shape.

**Simulated scenarios (avgDelta 2 — slightly worse than baseline).**
- Friday standup "what did I get done this week?" → clean status blurb with pinned range, but pure
  output-style shaping; nothing remembered or scaled. Baseline: the model already runs the git log
  and summarizes in one shot. **delta 2.**
- Sprint/PR-description prep over a tag range → tidy bulleted digest, but stops at ephemeral prose
  and doesn't wire to the next action. Baseline: commit-push-pr already generates a *richer*
  from-diff PR body (reads the diff, not just log messages) and wires it to the PR. **delta 2.**

**Benchmark check.** No benchmark and no usage/adoption numbers cited anywhere in SKILL.md
(WebFetch-verified). Only credibility is shipping inside Cursor's cursor-team-kit — weak
team-convenience evidence, not a measured gap. Prong-1 (evidenced recurring in-repo demand)
unmet: zero logged incidents in Overclock.

**Decisive reason.** Both moat axes absent and the buildable core is a single deterministic git
command the base model already wraps for free. Harmless but so thin that even ADOPT-AS-IS overstates
its value. PASS.

## Headline takeaway

All four ponytail-family commands plus karpathy-guidelines and what-did-i-get-done are
stateless prompt-shaping / single-command wrappers that touch **neither** Overclock moat axis
(memory, right-sizing). Five PASS, one INSPIRE. The only thing worth lifting is ponytail's
**non-negotiable safety floor** (never simplify away trust-boundary validation / security /
data-loss / a11y) — the single benchmark-verified differentiator after an independent reproduction
showed a one-sentence YAGNI prompt matched the 100-line persona — to fold into `/simplify` or a
CLAUDE.md altitude line.
