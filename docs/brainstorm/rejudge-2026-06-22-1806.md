# Re-judgment — prior candidates under the corrected usefulness bar (2026-06-22)

**What this is.** These are PRIOR skill candidates, previously KILLed, re-judged under the
**corrected bar** recorded in `../strategy.md` (Operating principles, "The bar is usefulness",
2026-06-22) and `.ai/memory/LESSONS.md`. The correction: **usefulness is the bar, not a
"memory + right-sizing moat."** A plain, stateless, well-designed skill that saves real time
every day is a GOOD skill. Moat (memory / right-sizing) is a **bonus signal, never a gate.**

Many earlier candidates were KILLed for "touching neither moat axis" / "stateless ceremony" /
"collapses to one always-loaded CLAUDE.md line" / "below the blast-radius bar." Those are
**moat-derived grounds the correction repudiates.** This pass re-judges the three candidates whose
kill rested wholly or partly on those grounds, on the corrected three-prong bar:
**(1) useful first** (stateless is fine), **(2) non-redundant** (kill only for true duplication,
not "lacks a moat"), **(3) well-designed** (right-sized, sane anti-triggers, should-NOT-trigger
evals).

## 1. repro-first — FLIPPED → STRONG

**Pitch.** Before fixing a reported bug, write a committed failing test that reproduces it, confirm
it fails *for the stated reason*, then fix until it passes. A reproduce-before-fix discipline gate
none of the feature-shaped tools enforce.

**Original kill reason (2026-06-17, KILL).** The grounding *admitted the seam is real* ("the
bug-shaped reproduce-before-fix seam is real" — feature-dev is feature-shaped with zero bug-repro
content, plan mode produces a plan not a failing test, all reviewers run after a diff exists, verify
is the POST-fix mirror). Killed anyway on three grounds: (1) "collapses to one always-loaded
CLAUDE.md line"; (2) "no memory axis"; (3) "right-sizing gate is binary one-liner-or-not, below the
blast-radius bar." Summarized as "stateless TDD ceremony on the saturated axis" + zero logged
incidents.

**Corrected grounding (verdict: useful-and-distinct).** Ran the non-redundancy test against every
overlapping tool; **none does the reproduce-before-fix job:**
- **feature-dev** — 7-phase guided FEATURE development; feature-shaped, grep-confirmed zero
  bug-reproduction / test-first content. Does not tell you to write a committed failing test that
  reproduces a reported bug before touching the fix. No overlap on the bug-repro seam.
- **plan mode** — produces a PLAN, not an executable failing test. No overlap.
- **/code-review, /security-review, pr-review-toolkit, code-review skill** — all run AFTER a diff
  exists; they review a fix, can't enforce a failing test was written first. No overlap on ordering.
- **/verify, /run** — the POST-fix mirror (confirm behavior AFTER the fix). repro-first is the
  PRE-fix gate (reproduce + confirm-it-fails-for-the-stated-reason). Complementary, not overlapping.
- **CLAUDE.md** — a buried always-loaded sentence with no triage gate, no "confirm it fails for the
  stated reason" step, no anti-triggers (it would nag on typo/config fixes). A triggered skill with
  should-NOT-trigger evals is strictly more reachable and reliable.
- **git bisect** — locates WHICH commit introduced a bug; a different job.

Every disqualifying ground in the original kill was moat-derived and is now invalid: "collapses to
one CLAUDE.md line" (a blast-radius sub-bar; a buried sentence is strictly weaker than a triggered
skill with a fail-for-the-stated-reason step), "no memory axis" (memory is a bonus), and
"right-sizing gate below the blast-radius bar" (itself a repudiated moat sub-bar).

**Scenarios (avgDelta 4).**
- *Login 500 on plus-sign email alias* (delta 6): baseline jumps to a plausible patch, often fixes a
  nearby-but-wrong cause, leaves no regression test; verify is a post-fix mirror that won't catch
  "fixed the wrong thing." With skill: committed red test on the alias path, confirm red matches the
  reported cause, fix to green → durable regression test + assurance the fix hits the real symptom.
- *Footer year string fix / axios dep bump* (delta 2): skill correctly should-NOT-trigger (anti-
  triggers: trivial typos, config/version bumps, pure refactors, no observable behavior); behavior
  identical to baseline. Confirms right-sizing, adds no everyday value here.

**Votes: 3/3 worth building.** Consensus: USEFUL (reproduce-before-fix is a high-frequency debugging
discipline AI agents reliably skip; the load-bearing "confirm it fails for the STATED reason" guards
against spurious passes and is what a buried CLAUDE.md line cannot enforce under urgency),
NON-REDUNDANT (the grounding itself conceded the seam is real and unowned; complementary to verify,
not duplicative), WELL-DESIGNED-ABLE (clean should-NOT-trigger evals: typo → no trigger, config bump
→ no trigger, new feature → defer to feature-dev). Weakest link (unanimous): **real-demand evidence**
— zero in-repo bug-repro incidents logged, so creation-bar prong 1 is unmet. This is a "gather
evidence / confirm recurrence before committing build time" caveat that gates WHEN it enters the
build queue, not WHETHER it is worth building.

**FLIPPED? YES.** Stripped of the three repudiated moat grounds, what remains is a stateless,
well-designed, daily-useful debugging discipline that no shipping tool enforces — the cleanest
acknowledged-real-seam case in the ledger. Verdict: **STRONG**, gated on demand evidence before
build.

## 2. review-router — UNCHANGED → KILL

**Pitch.** A right-sizing router for code review: triage a change by size/blast-radius and
risky-path signals, then delegate to the correct existing reviewer (no-op for trivial diffs,
/code-review for normal changes, escalate to /security-review on auth/crypto/migration/secret paths).

**Original kill reason (2026-06-16, KILL).** "Stateless ceremony in the most saturated space" and
"collapses into a mode that calls existing reviewers (workflow ceremony) on the most saturated axis";
the one novel bit (auto security-review on risky-path keywords) deemed "better served by an
update-config hook"; zero evidenced demand.

**Why reconsidered.** The dominant kill reason — "stateless ceremony on the saturated axis" — is the
off-axis/no-moat reasoning the correction overturns. Its near-twin super-plan-mode was only PARKED
(not killed) on the surviving-gap logic that "none of the tools scale rigor to task size," and
strategy.md endorses a "lightweight router that right-sizes and delegates upward" for planning —
an apparent asymmetry worth re-checking.

**Corrected grounding (verdict: redundant).** Re-judged under the corrected bar (moat no longer
required), it still fails the non-redundancy test — **for true duplication, not "lacks a moat."**
Decompose the three legs:
1. *"No-op for trivial diffs"* — a single anti-trigger line, and already the default (you simply
   don't invoke a reviewer on a one-liner).
2. *"/code-review for normal changes"* — just invoking /code-review, which **already exposes the
   effort tier as an argument** (low/medium/high/max/ultra). The router's only addition is picking a
   tier — a one-shot trivial judgment the user already makes when typing the command.
3. *"Escalate to /security-review on risky paths"* — by the candidate's own caveat, strictly better
   as a deterministic update-config hook (path-match trigger). An LLM skill is a worse implementation
   of a deterministic trigger (same shape as the invariant-guard / ship-switch-guard kills).

Net of the hook slice, the surviving contribution is "choose an effort argument for /code-review and
decide whether to bother" — which the effort parameter and existing command set already absorb. The
super-plan-mode asymmetry actually **cuts the other way and is consistent:** planning's right-sizing
is split across three distinct-altitude tools (bare plan mode / feature-dev / Ultraplan) with no
shared selector, so choosing among them is a real non-trivial decision worth parking; review's
right-sizing is **already solved inside one command** — /code-review's low→ultra effort scale IS the
router, internalized. Materially less surviving gap, which is exactly why one was parked and this
killed, consistently.

**FLIPPED? NO.** The kill survives the correction on a true-duplication / better-as-a-hook basis, not
on a moat basis. Verdict: **KILL** (still redundant under the corrected bar — existing tool does it
as well/better; the only novel leg is a deterministic-hook job).

## 3. tracker-sync (reconcile slice) — UNCHANGED → KILL

**Pitch.** After a change, reconcile the produced diff against the linked ticket's acceptance
criteria — flag criteria not yet met and out-of-scope work that crept in — before drafting the
PR/status update.

**Original kill reason (2026-06-17, KILL).** Duplicative (commit-push-pr writes from-diff PR bodies;
GitHub/Linear closing keywords auto-transition issues on merge). The one non-owned slice — diff-vs-
acceptance-criteria reconciliation — was dismissed as "stateless one-shot reasoning over two
in-context documents that collapses to a CLAUDE.md line; no memory/right-sizing edge" + inferred
demand.

**Why reconsidered.** The reconcile slice was explicitly the non-owned part, killed on the moat-
derived grounds the correction drops ("stateless one-shot," "collapses to a CLAUDE.md line," "no
memory edge"). "Did I satisfy every acceptance criterion / did I add scope creep" is a useful pre-PR
check. The honest test: does a focused skill measurably beat the unaided model? If not, it stays
killed for genuine base-model redundancy — which the correction does NOT excuse.

**Corrected grounding (verdict: narrow).** Explicitly NOT killed for stateless / no-memory /
collapses-to-a-CLAUDE-line. The coverage-check slice is **genuinely non-owned** by any installed
tool (commit-push-pr only describes the diff; closing keywords only transition the issue;
code-review/verify only check correctness; feature-dev's clarify phase scopes up front, not as a
post-change reconciliation). So it clears the **true-duplication gate on content.**

It fails the candidate's own honest test: reconciling a diff against acceptance criteria is **one-
shot reasoning over two documents already in context** (the diff + the ticket) — no mechanism, no
artifact, no signal the base model lacks. A competent model does it well the instant it's asked. The
skill's only real value is the **reminder** to run the check at PR-draft time — a habit/timing nudge
**better delivered as a one-line step inside commit-push-pr** (which already fires at the exact
PR-drafting moment) or CLAUDE.md, than as a standalone skill that must itself trigger and carry a
broad, fuzzy should-NOT-trigger surface (most changes have no linked ticket or written criteria).

**Scenarios (avgDelta 2).**
- *5-criteria feature, one criterion silently unbuilt + unrelated refactor crept in* (delta 3): real
  but thin gap; a competent model summarizing the diff against the in-context ticket routinely notes
  this when asked. Only thing the skill adds is reliably remembering to do it — a habit/timing gap a
  one-line commit-push-pr step closes.
- *One-criterion 8-line ticket* (delta 1): pure overhead; reconciliation value is essentially zero
  at this size; risks over-triggering on tickets with no enumerable criteria.

**Votes: 0/3 worth building.** Consensus: clears the content non-redundancy gate but fails on
**right-sizing/design** and **no measurable edge over the unaided model** — the entire useful effect
is a single reminder line inside an already-firing tool (commit-push-pr), and the standalone-skill
form adds a fuzzy should-NOT-trigger surface for a payload too small to justify it. Prong-1 demand
self-admitted inferred/zero; the near-identical ticket-to-contract was independently killed at zero
incidents across 335 transcripts.

**FLIPPED? NO.** Re-judged on the corrected bar (moat reasons dropped), it still fails — for
marginal-value + better-delivered-as-a-step-in-an-existing-tool, both of which the corrected bar
still kills for. Verdict: **KILL** (fold the reconcile reminder into commit-push-pr / CLAUDE.md as
one line; not its own skill).
