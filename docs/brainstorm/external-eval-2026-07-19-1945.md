# External skill evaluation — 2026-07-19-1945

**What this file is.** These are EXISTING, PUBLISHED third-party skills (Matt Pocock's
`mattpocock/skills` and EveryInc's `compound-engineering-plugin`) evaluated for **adoption into the
Overclock kit** — not internally generated ideas. The question per candidate: is it useful enough to
add, and if so via which path — ADOPT-AS-IS (install the published skill), BUILD-IN-OVERCLOCK (own a
tuned version), INSPIRE (lift one mechanism into an existing kit skill), or PASS. Redundancy is
scoped to the kit in `plugins/` only; ecosystem/base-model overlap is design context, not a kill.
Each candidate went through grounding (source verified against the live repos — the /tmp local
mirrors of mattpocock/skills were empty skeletons), scenario simulation with baseline deltas
(0-10), a benchmark/adoption-evidence check, and a 3-vote adversarial panel.

**Run tally: 14 candidates → 10 BUILD-IN-OVERCLOCK, 1 ADOPT-AS-IS, 2 INSPIRE, 1 PASS.**

**Cross-cutting findings.**
- The dominant reason ADOPT-AS-IS failed was never "not useful" — it was (a) in-kit trigger
  collisions (grilling and mp-tdd both claim "stress-test"/"fix bugs test-first" surfaces owned by
  critical-thinking and test-discipline), (b) house-invariant violations (CE skills auto-commit,
  push, post, or edit AGENTS.md/CLAUDE.md — directly against the no-auto-commit / explicit-write-scope
  contract), and (c) suite coupling (both source repos hard-reference sibling skills; CE's
  marketplace install is all-or-nothing across ~30 skills, several true-colliding with installed
  tools).
- The universal weakest link across panels: **demand is inferred, not logged.** Almost no candidate
  has a ledger incident or direct request behind it. Builds should be queued behind first real use,
  not started cold.
- Neither source repo ships a single benchmark. mattpocock/skills' ~177k stars and Every's
  production dogfooding are adoption/craft signals, not efficacy measurements.

**Pre-filtered (audited, not run through the gauntlet).** The two repos ship ~70 skills; 14
candidates were curated. Excluded with reasons:

- *In-kit / installed true-duplicates:* mp handoff + claude-handoff and ce-handoff (≈
  session-handoff), mp research (≈ independent-research + deep-research), ce-setup (≈
  overclock-setup), ce-simplify-code (≈ /simplify + code-simplifier), ce-code-review (≈
  /code-review + pr-review-toolkit), ce-commit + ce-commit-push-pr (≈ commit-commands),
  ce-worktree (Jean owns worktrees), ce-polish (≈ impeccable + /run).
- *Known KILL patterns:* mp git-guardrails (collapses to a deterministic update-config hook),
  ce-ideate (skill-brainstorm workflow owns ideation here).
- *No evidenced demand / other-owner:* mp triage, ask-matt, setup-matt-pocock-skills (infra for
  his fleet), teach, wizard, loop-me, resolving-merge-conflicts (minor; intent-tracing idea noted),
  ce-strategy + ce-pov (product-strategist adjacent), ce-promote, ce-explain, ce-optimize,
  ce-test-browser/xcode (/verify + /run own the surface), lfg (orchestrator over their pipeline).
- *Vendor-specific infra:* ce-proof, ce-product-pulse, ce-sweep, ce-riffrec-feedback-analysis;
  mp misc/personal/deprecated buckets (shoehorn migration, course scaffolding, obsidian vault).

Authoring-convention takeaways (leading words, CONCEPTS.md pattern, confidence anchors,
pass-paths-not-content, standing residuals, settled-decisions labels) are captured separately in
`docs/skill-authoring-notes.md` — they are conventions, not adoption candidates.

## 1. grilling — BUILD-IN-OVERCLOCK (3-0)

- **Source:** https://github.com/mattpocock/skills (skills/productivity/grilling + grill-me, skills/engineering/grill-with-docs)
- **Pitch:** Relentless-interview primitive: one question at a time, each with a recommended answer, facts-vs-decisions split, refuses to act until shared understanding is confirmed.
- **Baseline gap:** No kit skill does human-in-the-loop elicitation. Only neighbor is critical-thinking, and the overlap is trigger wording, not mechanism — the published description fires on "stress-test their thinking", a head-on collision with critical-thinking's committed "stress-test" trigger (opposite behaviors on the same phrase). AskUserQuestion / plan mode / feature-dev's clarify phase are agent-driven scoping flows, not a summonable interview. /simplify, code-simplifier irrelevant.
- **Benchmark check:** None. Author self-report ("load-bearing primitive of my fleet") + real design iteration (rejected question-cap feature). Demand signal, not measurement.
- **Simulation (avg 6.5):** pr-kit trust-model design interview (delta 6 — baseline batches 6 questions incl. ones answerable from strategy.md, then drafts on assumptions); shared-lesson-format migration (delta 7 — refuse-to-act gate holds exactly where acting early is irreversible).
- **Decisive reason:** The ~10-line primitive is worth owning nearly verbatim, but install-as-is breaks both hard rules: trigger collision with critical-thinking, zero anti-triggers, no agents/openai.yaml. Rebuild with elicitation-only triggers ("grill me", "interview me") + anti-triggers routing critique/verdict requests to critical-thinking; drop the /domain-modeling composition. Weakest link: no logged in-repo demand.

## 2. debugging-discipline (mp diagnosing-bugs + CE ce-debug, merged) — BUILD-IN-OVERCLOCK (3-0)

- **Source:** https://github.com/mattpocock/skills (skills/engineering/diagnosing-bugs) + https://github.com/EveryInc/compound-engineering-plugin (skills/ce-debug)
- **Pitch:** Hard debugging discipline: tight red-capable feedback loop before any theorizing (mp), assumption audits + falsifiable predictions per causal link (CE).
- **Baseline gap:** test-discipline owns the repro gate and the "fix this bug" trigger surface, but is a gate, not a methodology — no diagnosis discipline, and it stops on no-seam/flaky/perf bugs. The diagnosis middle (loop construction, minimisation, ranked falsifiable hypotheses, assumption audit, causal-chain gate, escalation triage) is unowned. Both published skills embed their OWN repro-test protocols on test-discipline's exact trigger → two divergent red-test contracts in-kit, the one redundancy that kills. ce-debug also commits/pushes/PRs on skill-owned branches (violates no-auto-commit) and is wired into the CE pipeline; mp hands off to /improve-codebase-architecture + CONTEXT.md/ADR conventions.
- **Benchmark check:** None from either source; "90% fixed once the loop exists" is rhetoric. Adoption is reputational (mp's audience; CE production use, already mined for pr-kit hardening 2026-07-17).
- **Simulation (avg 5.5):** intermittent race with no test seam (delta 7 — baseline anchors on "missing await" and adds a sleep); ordinary seamed bug (delta 4 — test-discipline already handles it; residual value is CE's causal-chain gate vs shallow symptom patches).
- **Decisive reason:** Build an owned skill that COMPOSES: delegate the red artifact to test-discipline's repro contract when a seam exists; own mp's Phase-1 loop ladder + minimise + tagged logs and CE's epistemics (assumption audit, causal-chain gate, escalation table); trivial-bug fast path + hard anti-triggers mandatory. Weakest link: the fuzzy hard-bug vs ordinary-bug triage line — if it's wrong, dueling ceremony on every failing test.
