## migration-safety-gate — KILL

- **Baseline-gap finding:** Duplicative. /code-review's published criteria already name "migrations that aren't backward compatible"; the dedicated ecosystem (strong_migrations, squawk ~600K dl/mo, eugene's dynamic lock tracing against a live PG, gh-ost/pt-online-schema-change, PlanetScale deploy-requests) owns this deterministically and strictly better. A file-editing skill cannot obtain the prod row-counts / lock traces its own moat requires — it must GUESS "plausibly large" (LLM vibes, not the advertised determinism). Surviving authoring-time slice collapses to a CLAUDE.md line + wiring squawk/eugene via a hook.
- **Sim:** not run.
- **Votes:** not cast (KILLed at grounding).
- **Decisive reason:** The moat signal (data volume / lock behavior) is structurally unobtainable by a file-editing skill, so the deterministic ecosystem does the core job measurably better; prong-1 demand self-admittedly zero.
