# External skill evaluation — 2026-06-25-1818

These are **EXISTING, PUBLISHED third-party skills** assessed for **adoption**, not internally
generated candidates. The question is never "is this a clever idea" — it is whether Overclock
should BUILD or ADOPT an equivalent, given (a) what Overclock already ships (session-memory:
lessons-learned/session-handoff, `/simplify`, code-simplifier, `/code-review`, feature-dev,
pr-review-toolkit, plan mode, CLAUDE.md as the always-loaded behavioral home) and (b) that the
skill is already freely installable as-is.

Verdicts: **ADOPT-AS-IS** (install the published skill, no Overclock-specific gap) /
**BUILD-IN-OVERCLOCK** (a real memory/right-sizing gap the published version misses) /
**INSPIRE** (lift one mechanism into an existing skill) / **PASS** (below the bar / duplicative).

## plain-writing — INSPIRE

- **Source:** https://github.com/shreyashankar/plain-writing-skill
- **Vote tally:** INSPIRE 1, ADOPT-AS-IS 1 → **final: INSPIRE** *(panel degraded: the 3rd adversarial
  vote failed on a StructuredOutput retry cap and did not land. Both recorded votes are non-BUILD; a
  hypothetical 3rd BUILD vote could not form a build majority either, so the "don't build" outcome is
  robust to the missing vote.)*
- **What it is:** A prose writing/editing skill enforcing a plain, anti-AI-tell style (simple
  words, one idea per sentence, NO em/en dashes, no jargon, no analogies, kill "delve"/"tapestry"),
  a two-pass revise-then-delete loop, and an `assets/revision_template.html` 3-tab report
  (original / revised / diff). The version evaluated here is the **Overclock-ADAPTED** one, with
  two differentiators the published skill lacks: (A) **personalization memory** — ingest the
  user's past writing, persist a per-user voice profile under `.ai/memory/`; (B) **precedence
  hierarchy** — generic baseline rules overridden deterministically by project/user layers. The
  absolute anti-AI-tell bans are treated as a credibility-signal FEATURE, not a defect.

### Baseline-gap finding
The adapted skill decomposes into parts Overclock already owns:
1. **Plain-style rules + anti-AI-tell bans + two-pass revision** = pure prose prompt-shaping,
   native-LLM, the saturated persona zone (strategy rule 2). This is the exact shape of the prior
   **ponytail INSPIRE** — a stateless always-on style persona — just pointed at prose instead of
   code. CLAUDE.md is already the always-loaded home for project style rules. The bans being a
   credibility-signal feature is granted, but a ban-list is still elicitable by a one-line prompt.
2. **HTML 3-tab diff report** = output ceremony (same judgment as ponytail-review's cosmetic
   tag-taxonomy footer).
3. **Personalization-memory (the one moat-touching part)** = a CONTENT-DOMAIN MODE of
   lessons-learned/session-memory: same `.ai/memory` contract, same evidence-counted /
   dedup-by-meaning / promote-to-CLAUDE.md loop. A learned voice preference ("user writes short
   declarative sentences", "user bans 'leverage'") IS a standing-rule entry lessons-learned
   already records. Same death shape as decision-log and repo-recon-memory ("a mode of
   session-memory at best").
4. **Precedence hierarchy (baseline < project < user)** = native instruction-layering; CLAUDE.md
   is already the project/user override home (cf. ai-client-context-sync KILL — merging
   instruction layers is native).

`/simplify` and code-simplifier are **code-only and never fire on prose**, so they add nothing on
the prose surface — but that absence is not a memory/right-sizing gap that justifies a rebuild;
it just means the prose domain is new. Strategy rule 1 requires a *measurable* baseline gap, not
domain-novelty, and every prior fresh-domain candidate (port-and-process-reaper,
deploy-provision-kit, profile-to-ranked-hotpath) still KILLed for zero evidenced in-repo demand.

### Benchmark check
No efficacy benchmark exists. The only quantitative signal is ~177 GitHub stars, which measure
template/idea popularity (the buzzy sibling corpus `mine-writing-rules`), NOT rewrite efficacy or
any edge over the bare model — the same discount applied to ponytail's and karpathy-guidelines'
stars. Decisively, even ponytail's *rigorous shipped* benchmark was found to attribute its wins to
the one-sentence YAGNI idea, not the 100-line persona, with a 3-word prompt matching it. By
analogy, a one-line "write in plain style, no em-dashes, kill 'delve'/'tapestry'" instruction
would capture most of plain-writing's value, so even a hypothetical benchmark would credit the
idea, not the scaffold. Prong-1 (evidenced recurring in-repo demand) is unmeasured and almost
certainly zero: Overclock's transcripts are code/dev-workflow, with no logged "rewrite this in my
voice" turns.

### Simulated scenarios (avg delta 3)
- **Multi-paragraph prose artifact, plain + in the user's voice (delta 4):** the skill enforces
  the anti-AI-tell ruleset, runs the two-pass loop, renders the HTML report, and matches a
  per-user voice profile in `.ai/memory/`. Voice-memory is the only moat-touching part; the rest
  is prompt-shaping + a report artifact. Baseline: Claude writes it, the user steers with one ask;
  the ruleset can live as a CLAUDE.md style block; lessons-learned already captures repeated style
  corrections and promotes them at 3+. No persisted voice profile and no HTML diff today.
- **Reword a single line — tooltip / error string / commit subject (delta 2):** the published
  skill has no triage gate, so it can fire the two-pass revision + full HTML report on a one-liner
  — pure ceremony that strategy rule 3 forbids. The Overclock adaptation must add a silent/no-HTML
  path, but that gate is equally fixable inside the published skill, so it is not a rebuild reason.
  Baseline already rewords instantly with no ceremony.

### Decisive reason
No Overclock-axis slice is done measurably worse by the published skill in a way that justifies a
rebuild. The one moat-touching adaptation (voice memory under `.ai/memory/`) is a content-domain
mode of the already-shipped lessons-learned, not a new skill — and it rests on prong-1 in-repo
demand that is unmeasured and almost certainly zero in a code-only repo. The persona/rules/HTML
parts are native-LLM + ceremony. The prose domain is genuinely new, but domain-novelty without
evidenced demand has KILLed every fresh-domain candidate, and right-sizing (no triage gate on
trivial text) is unmet by the published skill yet fixable *inside* it. Net: a prose user should
**install the published skill as-is**; Overclock should lift exactly ONE mechanism — treat a
learned writing-voice as an evidence-counted preference in `.ai/memory/`, promotable to CLAUDE.md
— into lessons-learned, mirroring the ponytail safety-floor sliver. That liftable, non-duplicative
mechanism is what makes this **INSPIRE rather than PASS**, gated on demand that is currently zero.
