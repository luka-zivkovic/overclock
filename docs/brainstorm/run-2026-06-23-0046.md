# Brainstorm run 2026-06-23-0046

**Summary:** Inner-loop / everyday-dev divergence run (8 candidates) under the corrected
usefulness-first bar. Two cleared to STRONG (characterization-tests, git-archaeologist); the other
six KILLed — five at grounding for true duplication / native-LLM-collapse, one (test-red-triage) for
true overlap with the STRONG repro-first sibling plus self-referential-audit collapse.

The run honored the mandate to explore the everyday inner loop (test-writing, refactors, debugging,
docs/onboarding, dependency maintenance, shell/infra) rather than re-litigate memory/review
territory. The two survivors share the SAME winning shape as the already-STRONG repro-first verdict:
a stateless, well-designed PRE-action discipline gate over native capability that agents reliably
skip — characterize-and-confirm-green BEFORE a refactor, and recover-historical-intent BEFORE
mutating defensive code. Both land on the artifact-to-action axis (existing behavior → committed
green tests; git history → recovered intent), with right-sizing as a bonus on characterization-tests.

Only the two survivors advanced to scenario-simulation + 3-vote skeptic panels. The six KILLs failed
at grounding (baseline-gap) and have null `sim` / empty `votes`.

## stale-doc-to-reality-diff — KILL
- **Moat axis:** artifact-to-action (prose doc → verified executable-claim diff); execute-the-doc as
  the claimed load-bearing edge, in a genuinely fresh docs/onboarding domain.
- **Baseline-gap finding:** Redundant. Deterministic CLIs already own "execute the doc": Runme
  (extract+run fenced blocks across runtimes), mdsh (`--frozen` CI freshness gate, purpose-built to
  keep READMEs in sync), codedown (extraction half). The "intelligent" residual — deciding which
  prose lines are executable claims, sequencing prereqs, diagnosing observed-vs-documented, suggesting
  the fix — is native LLM behavior with no signal a SKILL.md adds over the unaided read-and-run loop.
  Worse than baseline as an unattended "run EVERY documented command" runner: (1) safety — READMEs
  routinely include destructive/side-effecting steps (rm, docker prune, npm publish, curl|sh) a blanket
  runner doesn't guard against; (2) moat-signal-unobtainable — most README breaks are missing prereqs
  (Node/OS version, env vars, secrets, network) outside any file the skill sees, so it mass-reports
  false "broken" deltas that are really environment gaps.
- **Simulations:** none (failed grounding).
- **Skeptic votes:** none (did not advance).
- **Decisive reason:** True duplication (Runme/mdsh own execute-the-doc) + native-LLM-collapse of the
  residual. The docs/onboarding DOMAIN is fresh, but a developer reaches for Runme/mdsh or just asks
  the agent to run the README. Prong-1 self-admitted zero. Same shape that KILLed transcript-to-runbook.

## characterization-tests — STRONG
- **Moat axis:** right-sizing (bonus) — no net for a rename, focused golden-master for a gnarly
  untested function, defer to feature-dev for a real feature. Core is a stateless, well-designed
  discipline gate; artifact-to-action seam (existing behavior → committed green tests).
- **Baseline-gap finding:** useful-and-distinct. Approval/golden-master libraries (ApprovalTests,
  Verify, jest/vitest snapshots) own the ASSERTION mechanism but NOT the pre-edit ordering discipline,
  the triage of which seam to characterize, or the keep-it-green-THROUGH-the-edit gate — the exact
  unowned seam, structurally identical to why repro-first flipped to STRONG. The oracle is a REAL
  deterministic mechanism (committed tests run by the test runner), so it dodges the self-oracle trap
  that killed error-to-min-repro / claim-evidence-audit. Genuinely distinct from repro-first by
  POLARITY (green-preserve vs red-change) and trigger; cannot be folded into it without an
  assertion-level contradiction (red→green vs green→green invariance). /verify is the post-change
  mirror; /code-review runs post-diff; feature-dev is feature-shaped with zero characterization content.
- **Simulations (avgDelta 7):**
  - *180-line untested `computeInvoiceTotal` with accreted quirks (floor-before-sum, gold+>3-items
    loyalty discount, null-line-item returns 0), dev wants pure-helper split* — **delta 8.** Skill pins
    current outputs verbatim (quirks included) as committed green tests against pre-refactor code,
    refactors, keeps green; the floor-before-sum and null-returns-0 regressions are caught the instant
    the rewrite "cleans them up." Baseline rewrites + /verify on a happy path → silent penny-mismatch
    / new 500 ships with false confidence (no captured baseline).
  - *`parseUserAgent` WITH a test file, but tests only assert key presence (shape-only, not values);
    dev swaps regex chain for table-driven* — **delta 6.** Skill detects the tests are behaviorally
    thin, adds value-pinning characterization over real + garbage UA strings, catches silent
    reclassification and the changed empty-string fallback. Baseline: thin tests stay green before and
    after, so the behavior change is invisible; partial existing coverage makes the save real but less
    dramatic than the fully-untested case.
- **Skeptic votes:** 3/3 worthBuilding=true. All three: clears the corrected bar — USEFUL daily
  (refactoring untested code is among the highest-frequency AI-assisted tasks; agents reliably
  rewrite-then-"verify" with no captured baseline), NON-REDUNDANT (libs own only the assertion; the
  pre-edit triage + confirm-green-BEFORE + keep-green-THROUGH discipline is unowned; deterministic
  oracle dodges the self-oracle trap), DESIGNABLE (clean should-NOT-trigger evals: rename/typo/config
  = no trigger, already-tested code = no trigger, new feature = defer; right-sizing bonus). Demand
  (likely zero in-repo, same as repro-first) gates WHEN/HOW, not WHETHER. Unanimous weakest link:
  PACKAGING overlap with the STRONG repro-first sibling — two test-discipline-gate skills both fire on
  "about to touch under-tested code"; the strongest design may be ONE "test-around-your-edit" skill with
  two modes (red-for-bug / green-for-refactor).
- **Decisive reason:** The characterize-and-confirm-green-BEFORE-the-refactor seam is genuinely
  unowned and the candidate has no prior verdict (not re-litigation). The single thinnest point is
  packaging overlap with repro-first — a design/sequencing call (one-skill-two-modes vs two skills),
  not a redundancy kill — which must be resolved, alongside confirming in-repo demand, before either
  ships standalone.

## git-archaeologist — STRONG
- **Moat axis:** artifact-to-action (git history → recovered-intent discipline); stateless, no
  persistence. The edge is the enforced discipline of consulting history BEFORE mutating defensive
  code — the same shape as the STRONG repro-first verdict, not a new mechanism.
- **Baseline-gap finding:** narrow → flipped to build by the panel. Clears true-duplication: no
  shipping tool recovers historical intent before an edit (the agent HAS git/gh and CAN blame, but
  by default does NOT correlate blame→introducing-commit→linked-PR at mutation time; /code-review and
  /security-review are post-diff, /verify is the post-fix mirror, feature-dev is feature-shaped). The
  save is real and bites AI agents HARDER than humans — they confidently flag defensive code (a guard,
  retry, "redundant" check) as cruft and silently undo a deliberate fix (the guard added in #412 to
  fix a race). The grounding's "narrow" verdict rested on (a) zero in-repo demand and (b) a fuzzy
  trigger; under the corrected bar (a) gates WHEN to build (per the repro-first precedent), and (b) is
  a fixable design problem.
- **Simulations (avgDelta 4):**
  - *"Clean up" a payment handler with a weird `await sleep(50)` + an `if (retryCount>0)` idempotency
    block; both added in PR #412 to fix a duplicate-charge race, documented in the commit + linked
    issue* — **delta 6 (best case).** Skill fires on load-bearing/surprising code, blames the lines,
    reads #412, surfaces a Chesterton's-fence warning ("removing the idempotency key reintroduces
    double charges"); dev keeps the guard. Baseline, told to "remove dead-looking code," pattern-matches
    the magic sleep + redundant-looking conditional as cleanup targets and strips them → the
    duplicate-charge bug silently returns.
  - *Mid-refactor `// eslint-disable-next-line` + explicit cast added in a vague "fix build" commit
    with no linked PR; the real reason lived in a dead Slack thread* — **delta 2.** Skill fires, blames,
    finds no recoverable intent, can only report "introduced in <sha>, no linked PR/issue, intent
    unrecoverable" after spending a blame+log+show round-trip; marginal value, and the trigger risks
    firing repeatedly on routine refactors. Baseline either leaves the cast alone (common safe default)
    or removes it and CI catches the build break — about the same outcome, since history has nothing.
- **Skeptic votes:** 3/3 worthBuilding=true. All three: the underlying discipline is genuinely useful
  and universal (silently undoing a deliberate fix when touching code you didn't write is a costly
  everyday failure mode, especially for agents); clears true-duplication (no tool enforces
  recover-intent-BEFORE-the-mutation); same "enforce a discipline agents skip" shape that flipped
  repro-first; zero in-repo demand gates WHEN, not WHETHER; designable IF re-anchored. Unanimous
  weakest link: the as-pitched trigger ("surprising or load-bearing code") is subjective and
  self-referential — the agent must already judge code surprising before the discipline engages, which
  is the very blind-spot the skill backstops, so it risks NOT firing exactly when most needed. Must be
  re-anchored to a concrete structural ACTION CLASS (before deleting/weakening a guard, early-return,
  retry, sleep, lock, clamp, or seemingly-redundant check) with a crisp should-NOT-trigger surface
  (new code, pure additions, renames, formatting, code with no prior history).
- **Decisive reason:** Genuinely useful + non-redundant + designable under the corrected bar — the
  recover-intent-before-edit seam is unowned and the failure it prevents is real and AI-specific. The
  load-bearing condition for ship is re-anchoring the trigger from the subjective "surprising" to a
  structural defensive-code-mutation pattern-list, plus gathering ≥2-3 real in-repo "I almost deleted
  a deliberate fix" incidents before committing build time.

## Run takeaways
- **2 STRONG, 6 KILL.** First run since the 2026-06-22 correction to surface NEW STRONG candidates:
  both survivors share repro-first's winning shape — a stateless PRE-action discipline gate over native
  capability that agents reliably skip, with a DETERMINISTIC oracle or a CONCRETE artifact (committed
  tests; git history) rather than the LLM auditing itself. That distinction is what separated them from
  test-red-triage (self-referential audit) and from the docs/shell KILLs (moat-signal-unobtainable).
- **The dominant KILL pattern held for the six rejects:** owned-by-deterministic-CLI / installed-MCP
  (Runme/mdsh, bumpgen + GitHub native Dependabot-to-agent, context7's standing instruction,
  just/Makefile/atuin) + native-LLM-collapse of the residual; plus one true-overlap-with-a-STRONG-sibling
  (test-red-triage ↔ repro-first).
- **Shared open question across BOTH survivors and repro-first:** packaging. The repo would now carry
  three pre-action discipline gates (repro-first, characterization-tests, git-archaeologist). repro-first
  and characterization-tests are operationally near-identical ("commit a test around your edit") and may
  be ONE two-mode skill; git-archaeologist needs its trigger re-anchored from subjective "surprising" to
  a structural defensive-code-mutation pattern-list. None should ship before resolving packaging and
  gathering real in-repo demand (prong-1 currently ~zero for all three).
